# Нагрузка VCam

Видео передаётся напрямую через WebRTC, без TURN-реле. В обычной домашней сети поток остаётся между телефоном и компьютером; маршрут выбирает WebRTC. Сервер VCam не принимает видеокадры и не записывает видео. CPU/GPU, кодирование и основная пропускная способность нужны устройствам пользователя и Wi-Fi.

Сервер обслуживает HTML/ресурсы сайта, создаёт одноразовую сессию, хранит хеши ключей и кода, обменивает SDP и удаляет завершённые/устаревшие записи. До соединения Windows опрашивает ответ раз в 2,5 секунды, телефон — раз в 0,8 секунды. После согласования соединения этот опрос прекращается. Длительность уже установленной видеотрансляции не добавляет API-запросов VCam. STUN используется для установления прямого соединения и не ретранслирует медиапоток.

Приблизительное число запросов подключения: 5 служебных запросов + опрос Windows (время ожидания / 2,5 секунды) + несколько запросов телефона. Если пользователь оставил QR на десять минут, один Windows-клиент может сделать около 240 запросов опроса до истечения срока. Это оценка по коду, не измерение производственной нагрузки.

Поэтому нагрузка растёт с посещениями, новыми сессиями, ожиданием QR и ошибочными попытками, а не с числом часов видеосвязи. Мокапы оптимизированы в WebP, установщики скачиваются с GitHub Releases. Для реальной оценки нужны статистика запросов и квоты аккаунта Sites: тариф Cloudflare напрямую не равен условиям управляемого Sites-хостинга. Не следует обещать неограниченный бесплатный хостинг без этих данных.

Если позднее добавить TURN для сложных сетей и разных Wi-Fi, реле будет пропускать весь видеопоток. Например, 5 Мбит/с — примерно 2,25 ГБ видео за час в одном направлении. Тогда трафик станет главным расходом; текущая версия такого расхода на сервере VCam не создаёт.

Бесплатность приложения можно сохранять, отделяя её от стоимости инфраструктуры. Для масштабирования важны кэширование статических ресурсов, ограничение попыток, уборка сессий и уменьшение опроса. В коде уже есть одноразовые хешированные ключи/коды, индексы базы и ограничения запросов. Рекламные SDK, аналитические трекеры и платные функции не добавлены.

Справка: [WebRTC connectivity](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Connectivity), [Cloudflare Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/).
